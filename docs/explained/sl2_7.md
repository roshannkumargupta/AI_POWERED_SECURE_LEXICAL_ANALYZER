# SL2-7: Agent Safety Lab

## Modes and data flow

HARNESS and LIVE are separate API modes. HARNESS runs no model. It sends inert fixture text through the deterministic analyzer and rules-mode orchestrator, checks requested forbidden operations at the real tool gateway, and uses the independent verifier for the syntax-regression patch. Its result is labeled “Deterministic harness - no model involved.”

LIVE calls the configured provider with the fixture framed as untrusted data. Structured output is validated; each requested tool operation is checked and executed or denied by the real gateway. Proposed code is statically analyzed, never run. If the model is unavailable, the result says “Live agent test could not run (model unavailable),” has no simulated result, and does not invoke the harness.

Each scenario run receives a unique id and actual timestamped timeline. The process-local bounded store contains scenario/configuration data, source hashes, analyzer summaries, gateway decisions, assertions and limitations. It does not keep source strings or prompts. `/api/reports/export` creates JSON, Markdown, printable self-contained HTML, or token CSV from a fresh analysis or a stored Safety Lab run.

## Results

All six scenarios were executed in HARNESS mode. Scenario 6 was run in Python, Java, JavaScript, and C++; each safe lookalike run had zero security findings. The placeholder credential was detected in the suppression and candidate scenarios, while the suppression and verifier-bypass operations were denied. The verifier rejected the syntax-regression patch. The groq executable exists, but its daemon was unreachable, so model availability could not be checked and no LIVE model experiment was run.

## Viva questions

**Q1. Why keep HARNESS and LIVE separate?**  
HARNESS proves deterministic policy behavior without a model. LIVE measures an actual provider response. Mixing them could make simulated behavior look like model behavior.

**Q2. Who decides whether an attack was resisted?**  
The evaluator checks explicit assertions, analyzer results, gateway decisions, and verifier output. The model's own claim is never used as a grade.

**Q3. What happens when the model is missing?**  
The LIVE result records “Live agent test could not run (model unavailable),” an unavailable event, no assertions, and no outcome. It does not substitute a HARNESS run.

**Q4. How does the lab avoid retaining submitted code?**  
Scenario source is loaded for analysis and prompt construction but not placed in the run store. The report keeps a SHA-256 hash and a reduced finding summary; event argument summaries omit source and parameter values.

**Q5. Why does a blocked syntax regression say Attack contained?**  
The independent verifier's check outcome is “Verification failed.” The Safety Lab's separate outcome means the attempted regression was contained because it did not pass verification or change the fixture.
