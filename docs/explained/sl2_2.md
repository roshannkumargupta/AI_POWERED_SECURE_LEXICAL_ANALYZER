# SL2-2: token projection and lexical conformance

## Viva questions

1. **Why do token offsets have two forms?** Editors commonly index UTF-16 code units while Python indexes Unicode code points; keeping both prevents emoji and other non-BMP characters from shifting ranges.
2. **Why are whitespace and newlines not visible tokens?** The token table is for meaningful lexical units, while the lossless scanner stream retains trivia so the exact source can be reconstructed.
3. **Can a syntax error make a token lexically invalid?** No. Lexical status is assigned from lexical errors only; parser status is a separate dimension.
4. **What does a conformance count prove?** Only how the scanner compared with the chosen oracle on the files and grammar versions actually run. It does not prove full language compliance.
5. **What happens when a lexer cannot classify a kind?** The mapper gives it a language-specific name and does not invent a security label; further diagnostics require explicit evidence.
