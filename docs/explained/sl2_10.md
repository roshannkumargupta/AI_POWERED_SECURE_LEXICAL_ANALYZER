# SL2-10 Viva Questions and Answers

1. **Why is the overall acceptance status partial?**
   Because UI unit tests, Ruff and the production build passed, while mypy failed, full pytest did not yield a result, and browser E2E was denied before setup. A build is not browser acceptance.

2. **Why exclude `examples/` from Ruff?**
   These are submitted-code fixtures meant to be invalid, suspicious or vulnerable. Linting them as repository implementation code reports expected fixture properties as project defects. They remain available to lexer/analyzer tests.

3. **What does a missing compiler or analyzer mean?**
   That check is unavailable and the analysis is incomplete for that dimension. It does not imply the source passed that check.

4. **What does “verified” mean for a patch?**
   Only that the independent verifier's named checks ran and met their stated conditions. It does not prove runtime correctness or replace the user's project tests.

5. **Can AI or deterministic static analysis establish safety?**
   No. Rules and tools have coverage limits and can miss issues or report false positives. AI output is advisory and source should be reviewed; unavailable checks and assumptions must remain visible.
