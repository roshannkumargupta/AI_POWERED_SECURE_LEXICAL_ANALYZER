# SL2-1 Viva Notes: Versioned Analysis Contracts

## 1. Why add a v2 result model instead of changing the current models?

The existing pipeline and clients use `AnalysisResult`. Changing that shape during migration could break them. `AnalysisResultV2` is additive, and `adapt_analysis_result` maps the existing engine output into the typed v2 contract. `/api/analyze` continues to return v1 by default and selects v2 only for `api_version: 2`.

## 2. Why does each token expose both UTF-16 and code-point offsets?

The editor uses UTF-16 code units while Python indexes Unicode code points. An emoji occupies two UTF-16 units but one Python code point. The adapter preserves the lexer’s UTF-16 offsets and uses `OffsetMap` for code-point offsets, while line and column values stay one-based and editor-compatible.

## 3. How does stale-result handling work?

The request carries a client-managed monotonic `source_version`. The response echoes that value and includes the SHA-256 hash of the exact UTF-8 source. `result_matches_source` accepts a result only if both match the current text and version. This prevents an older response from replacing newer editor state.

## 4. What prevents an analyzer from executing submitted source?

The static runner has an executable allowlist and fixed per-tool argument profiles. It stores source under a fixed basename in a random temporary directory, uses argument arrays with `shell=False`, removes the directory, and bounds process time and captured output. It never selects a runtime profile for submitted source. Because this Windows host does not provide an OS-enforced network sandbox, external analyzer execution currently fails closed as unavailable; discovery and version reporting still work.

## 5. What does a passing adapter test prove, and what remains unverified?

The SL2-1 tests validate model round-trips, source hashes, offsets, stage filtering, tool safety behavior, and adaptation for all 260 source fixtures. OpenAPI schema generation and the synchronous capability builder are covered. They do not prove that the API is reachable over HTTP in this environment: the sandbox blocks the local socket pair used by Windows asyncio/Starlette TestClient. A normal host needs to run the live endpoint and verify tool capability output and an API-v2 sample response.
