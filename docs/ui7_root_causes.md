# UI-7 root causes and fixes

| Defect | Evidence and root cause | Fix in this phase |
|---|---|---|
| Native controls could use light browser styling or black `buttontext` | Before scan at 1536×1022 recorded root `colorScheme: normal` and 22–33 controls outside dark scheme in `reports/ui7/before/`. `tokens.css` had no root `color-scheme`, and only buttons inherited font. | Set `color-scheme: dark`; controls inherit font/color, select/option/placeholder/disabled/focus styling is explicit. |
| Low contrast on primary actions | Before diagnostics measured white on `--accent` (`#6DA7EC`) at 2.50:1 for Fix all. `TopBar.tsx` used white foreground over that light blue accent. | Use the dark surface text token on active Analyze and Fix all buttons; text/accent pair exceeds 4.5:1. |
| Security highlight contrast scan false positives | `.sl-insecure` used translucent amber without an explicit foreground; diagnostic treated rgba alpha as opaque. | Alpha-composite ancestor backgrounds in `web/qa/diagnostics.js`; retain the semitransparent highlight and explicit token foreground in base theme. |
| Multi-file tab row collapsed and overlapped content | Opening the lexical demo created two editor documents. Browser geometry showed `.ui6-tabs` had a 0–14 px height and `flex: 1`, because `.ui5-editor > :first-child` gave the tabs the editor's flexible height. | Give the flexible slot to the editor content child and exclude tabs and legend; the file tab row measured 30 design px after the fix. |
| Narrow responsive panel wrapper could create an additional scroll container | `ui5.css` set `.ui5-panels { overflow:auto }` below 1099 px and its children had forced minimum heights. This nested scroll ownership and clipped editor/table regions. | Keep the panel group clipped, set panel flex items' min dimensions to zero, and allow the narrow stacked panel wrapper to scroll only below 768 px. Inner tables/flyouts retain their own scroll areas and overscroll containment. |
| Fixed pixel metrics did not respond to requested design frame | Existing component metrics were fixed px; no viewport scale existed. | Added scale function using the specified 768×480 frame, root-frame transform, resize scheduling, persisted 0.85/1/1.15 interface size, and Monaco's 12 px base font. This is an implementation approximation: existing component styles remain authored in px rather than all being migrated to rem. |
| Diagnostics reported intentionally clipped editor/accessibility controls | Monaco's screen-reader textarea is transparent and 1 px; the top-bar hidden language label is clipped by design. | Exclude these known nonvisual nodes from clipping/control checks; keep the exclusion in the diagnostic source. |

The target image and `ref_metrics.json` named by the phase brief are not present in `docs/ui_reference/`; that folder contains only its README. Therefore this report does not claim pixel-diff matching or target-image-derived measurements.
